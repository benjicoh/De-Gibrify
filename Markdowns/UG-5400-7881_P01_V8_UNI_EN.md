# CARTOUNIVU™ Module Overview

https://bwiildita.sharepoint.com/sites/prod/Topics/fluoroBG\_overview\_c3\_v7\_EN.xml

With the **CARTOUNIVU™ Module**, fluoroscopic captures (images and cine clips) can be imported to and displayed in the CARTO™ 3 System.[[1]](#footnote-1)

These images are not for diagnostic purposes.

When fluoroscopic captures are integrated into the CARTO™ 3 System map viewers (Main Map Viewer and Additional Map Viewer), CARTO™ 3 Maps, MRI or CT images, and catheter visualizations are superimposed on the fluoroscopic capture.

In order to work with the CARTOUNIVU™ Module, the following is required:

* Dedicated installation and initial calibration

The CARTOUNIVU™ Module installation is unique to a specific Location Pad, Registration Plate, fluoroscopy system, and EP lab.

* Registration between the fluoroscopy system and the CARTO™ 3 System for each procedure.

The CARTOUNIVU™ Module extends the working range of the fluoroscopy system (SID, table height, etc.) during a CARTO™ 3 Procedure. After registration, you can work with the detector positioned closer to the patient and with the patient table lowered closer to the collimator.

# Safety

https://bwiildita.sharepoint.com/sites/prod/Topics/fluoroBG\_safety\_c3\_v3\_EN.xml

All safety considerations, cautions, and warnings that apply to the general use of the CARTO™ 3 System also apply while using this module. In addition, the following considerations apply:

* Fluoroscopic images displayed in the CARTO™ 3 System are provided for orientation only. They are not for diagnostic purposes.

REP4611 1.2.1.1, V3 tab

* The CARTOUNIVU™ Module installation is unique to a specific Location Pad, Registration Plate, fluoroscopy system, and EP lab.

REP4611 1.6.1.6, v3 tab; REP4611 1.6.1.7, v3 tab, REP4611 A-V3-1.6.1.2, PL.22

* Do not capture images in the fluoroscopy system when the C‑Arm or table is in an unsupported mode.

REP4611 1.6.2.2, v3 tab; REP4611 1.6.4.1, v3 tab

* Fluoroscopic captures are not gated according to heartbeat or respiration. If possible, manually gate the fluoroscopic captures to the end-expiration and end-diastole phases.
* Functionality of the CARTOUNIVU™ Module depends on access to information from the connected fluoroscopy system. If connection to the fluoroscopy system is via the hospital network and communication is lost (due to failure of the network or physical disconnection), new fluoroscopy captures cannot be acquired until the connection is restored. The module can still be used with captures attained previously.

REP4611 1.6.1.11, v3 tab

* In case of a communication failure with the fluoroscopy system, it is recommended to review points acquired during the last few minutes.

### Inverse Capture Orientations

https://bwiildita.sharepoint.com/sites/prod/Topics/fluoroBG\_receivingCaptures\_inverse\_c3\_v3\_EN.xml

Every capture automatically includes an inverted orientation capture. A capture taken in AP orientation corresponds to AP and PA in the CARTO™ 3 System; RAO corresponds to RAO (Right Anterior Oblique) and RPO (Right Posterior Oblique), and so on.

If the fluoroscopy system supports rotational angiography, a 180° rotational scan can be sent to the CARTO™ 3 System (images only). One image is assigned to each orientation region and its inverse, providing 360º coverage. Each orientation region in the CARTO™ 3 System represents a 5º wedge.

### Viewing Captures in Review Mode

https://bwiildita.sharepoint.com/sites/prod/Topics/fluoroBG\_reviewMode\_c3\_v3\_EN.xml

### Rescaling Fluoroscopic Captures

https://bwiildita.sharepoint.com/sites/prod/Topics/fluoroBG\_repositioning\_v4-2\_EN.xml

Fluoroscopic captures are presented in a perspective view, where closer objects appear smaller. In the CARTO™ 3 System, objects always appear the same size, regardless of distance. Because of this difference in presentation, captures are scaled when they are received by the CARTO™ 3 System.

When a new capture is received, its position in the CARTO™ 3 System map is determined according to a region of interest defined by the position of the catheter connected to the MAP socket. If the MAP catheter is not connected, the System searches for an alternative catheter that is connected to the 20 POLE A, 20 POLE B, ULTRASOUND, or REF/DECA socket (in that order). If no catheter is connected when the capture is received, the region of interest will be defined by the fluoroscopy system's isocenter level.

To avoid compromising the alignment between the fluoroscopic capture and the CARTO™ 3 System map, it is recommended to position a catheter that is connected to one of the previously mentioned PIU sockets in the chamber of interest when receiving a new capture.

If captures were received when there was no catheter in the relevant chamber or if the region of interest changed, you can rescale the previously acquired captures according to current catheter position. (This applies only to captures that are currently displayed in the map viewer.) To rescale the currently displayed capture, place the catheter in the appropriate chamber and then click ![fbg_reposition_icon.png](data:image/png;base64...) on the CARTOUNIVU™ Toolbar.

## Handling Movement

https://bwiildita.sharepoint.com/sites/prod/Topics/fbg\_handling\_movement\_EN.xml

The CARTO™ 3 System uses the positions of the three Back Patches, relative to each other and to the Location Pad, to determine the initial Location Reference (Patient Body Reference).

If all three Back Patches move together, keeping the same relative orientation, the System cannot tell if the change was due to Back Patch movement or Location Pad movement. During a standard CARTO™ 3 Study, the System compensates for this movement. However, if this happens during CARTOUNIVU™ Module registration, the System cannot compensate. A System message appears, with instructions for resolving the issue.

![msg_possibleLPMove.png](data:image/png;base64...)

Figure 7: System Message: Possible Location Pad Move

|  |  |
| --- | --- |
| If the Location Pad moved: | * Click LP Moved. * Perform Registration again.   Captures taken before this new registration will be rejected. |
| If there was no Location Pad move: | Click No LP Move.  Captures taken from the previous registration are still valid. |

When the System detects that the relative distance between the Back Patches has changed, it suspects that it is due to patient movement. A System message appears, notifying you that it cannot compensate for this movement and providing instructions for resolving the issue. If the issue cannot be resolved, you will be prompted to learn a new location reference and perform Initialization of catheter visualization again.

![msg_patchMove.png](data:image/png;base64...)

Figure 8: System Message: Possible Patient Move

Existing captures are marked as being from the previous Location Reference.

In some cases, there might have also been a Location Pad move. After learning the new Location Reference, you will be prompted to verify whether the Location Pad moved. Click LP Moved or No LP Move as described above.

|  |  |
| --- | --- |
| Location Reference move, no Location Pad move: | * Captures taken from the previous registration are still valid. * Existing captures are marked as being from the previous Location Reference. * Captures taken before learning the new Location Reference will be rejected if sent to the CARTO™ 3 System. |
| Location Reference move and Location Pad move: | * Existing captures are marked as being from the previous Location Reference. * Captures taken before learning the new Location Reference and before the new registration will be rejected if sent to the CARTO™ 3 System. |
